05 — Code Review & Technical Evaluation

I read code the way a compiler can't.

Whether it's a teammate's pull request or AI-generated training data, I evaluate code against a clear rubric — and explain the reasoning step by step.

01

Correctness

Bugs, edge cases, off-by-ones and broken invariants.

02

Security

Injection, auth flaws, unsafe input handling and secrets.

03

Performance

Complexity analysis, bottlenecks and concrete optimizations.

04

Maintainability

Readability, code smells, SOLID and idiomatic style.

05

Trade-offs

Comparing implementations and explaining which wins and why.

review: users/query.py
-sql = f"SELECT * FROM users WHERE id = {user_id}"
-return db.execute(sql).fetchall()
+sql = "SELECT id, name, email FROM users WHERE id = %s"
+return db.execute(sql, (user_id,)).fetchone()
CSChristian requested changes
  1. Security f-string interpolation allows SQL injection — use a parameterized query.
  2. Perf SELECT * over-fetches; select only needed columns.
  3. Correctness lookup by PK returns at most one row — fetchone() matches intent.
